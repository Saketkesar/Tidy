--------------------------------------------------------------------------------
1. NO DUMMY DATA RULES (HARD REQUIREMENTS)
--------------------------------------------------------------------------------
- Every number, file name, size, path, percentage and chart in the UI must come
  from the real machine at runtime. Nothing hardcoded.
- No placeholder lists, no "Lorem ipsum", no sample files, no fake apps, no
  fake sizes like "12.4 GB" in code, previews, or previews-in-SwiftUI shipped
  to the user.
- Progress bars must reflect real scan progress (files scanned / estimated
  total, or indeterminate spinner if total is unknown). Never fake-animate to
  100%.
- If a scan finds nothing, show a real EMPTY STATE ("Nothing to clean here"),
  not invented results.
- If permission is missing, show a PERMISSION STATE, not fake data.
- SwiftUI #Preview blocks may use test fixtures, but fixtures must live in a
  separate Preview target / #if DEBUG and never ship in release builds.
- Disk totals come from URLResourceValues:
  volumeTotalCapacityKey, volumeAvailableCapacityForImportantUsageKey.
- File sizes come from URLResourceValues: totalFileAllocatedSizeKey
  (fallback fileAllocatedSizeKey). Directory size = sum of children, computed
  by real enumeration.

--------------------------------------------------------------------------------
2. SAFETY RULES (HARD REQUIREMENTS)
--------------------------------------------------------------------------------
Cleaning apps can destroy user data. These rules are not optional.

S1. NEVER permanently delete by default. Cleaning = move to Trash using
    FileManager.trashItem(at:resultingItemURL:). Offer "Delete permanently"
    only as a separate, explicit, confirmed action in Settings (off by default).
S2. NEVER touch these paths (hard blocklist, enforced in one central function
    isPathProtected(url) that every delete/move path must call):
      /System, /usr, /bin, /sbin, /private/var/db, /Library/Apple,
      /Applications (apps are only removed through the Uninstaller flow),
      ~/Documents, ~/Desktop, ~/Pictures, ~/Movies, ~/Music
      (except where the user explicitly selects an item in Large Files or
       Duplicates and confirms),
      ~/Library/Keychains, ~/Library/Mail, ~/Library/Messages,
      ~/Library/Application Support/AddressBook,
      ~/Library/Mobile Documents (iCloud Drive),
      any path inside a Photos library or Time Machine local snapshot.
S3. Resolve symlinks before checking paths (use resolvingSymlinksInPath) so a
    symlink cannot smuggle a protected path into a clean list.
S4. Cache/log cleaning only targets the whitelist in section 6. Anything not on
    the whitelist is never auto-selected.
S5. Never clean files currently in use. Before cleaning a cache folder for an
    app, check NSWorkspace.shared.runningApplications for that bundle ID. If
    running, mark the row "App is open - quit it to clean" and skip it.
S6. Every cleaning action shows a REVIEW screen first: what will be removed,
    real sizes, real paths, checkbox per item. Nothing is deleted until the
    user presses the confirm button.
S7. After cleaning, show a real result: bytes actually freed (compare volume
    free space before/after AND sum of trashed item sizes). Keep a local
    history log so the user can see what was moved and restore it.
S8. Provide "Undo last clean": restore items from Trash to original paths using
    the saved resultingItemURL + original URL pairs. If Trash was emptied,
    say so honestly.
S9. Dry-run mode: Settings toggle that scans and reports but disables the
    confirm button. Useful for testing.
S10. Never send file names, paths or any scan data off the device. No network
     calls for core features. No analytics that include file info.

5.7 DUPLICATES

+----------------------------------------------------------------------+
|  Duplicates                       Scan in: {folder list}   [ Scan ]  |
|----------------------------------------------------------------------|
|  Group 1 - {n} copies, {size each}, wasting {size}                   |
|    ( ) {path 1}   {date}                                             |
|    (x) {path 2}   {date}   <- user picks which to REMOVE             |
|    (x) {path 3}   {date}                                             |
|  ...                                                                 |
|  Always keep at least one copy per group (UI enforces this).         |
|----------------------------------------------------------------------|
|  Will remove {n} files, free {size}   [ Move selected to Trash ]     |
+----------------------------------------------------------------------+
Algorithm (real, no shortcuts):
  1. Enumerate files, group by exact byte size (skip size 0 and tiny < 4 KB
     optionally).
  2. For same-size groups, hash first 64 KB (fast filter).
  3. For remaining matches, full-file SHA-256 (CryptoKit), streamed in chunks.
  4. Group by full hash. Only groups with 2+ files are shown.
Default selection: none. Suggest "keep oldest" / "keep newest" quick buttons.

Two modes: manual "Organize now" and optional live "Auto-organize".

|  +----------------------------------------------------------------+  |

|  | [x] Documents  ext: pdf doc docx txt rtf pages md    -> Docs   |  |

|  | [x] Slides     ext: ppt pptx key                     -> Slides |  |

|  | [x] Video      ext: mp4 mov mkv avi                  -> Video  |  |

|  | [x] Code       ext: py js ts swift c cpp java json   -> Code   |  |
|  | [ ] Everything else                                  -> Other  |  |
|  +----------------------------------------------------------------+  |
|  [ + Add rule ]   (name, match by: extension / name contains /       |
|                     source app / size / age -> destination folder)   |
|                                                                      |
|  Destination root: ~/Downloads/Sorted  [ Change... ]                 |
|                                                                      |
|  [ Preview what will move ]                                          |
+----------------------------------------------------------------------+

Preview screen (REQUIRED before first run and available always):
+----------------------------------------------------------------------+
|  Preview - {n} files will move                                       |
|  {file name}      {size}     -> Sorted/Images/                       |
|  {file name}      {size}     -> Sorted/Documents/                    |
|  ...                                                                 |
|  Skipped: {n} (still downloading, hidden, folders, already sorted)   |
|            [ Cancel ]   [ Organize ]                                 |
+----------------------------------------------------------------------+

Rules for the organizer engine:
- Moves, not copies, within the same volume (FileManager.moveItem) so it is
  instant. If destination is on another volume, copy + verify + trash source.
- Skip: files ending .download .crdownload .part .tmp (in-progress), dotfiles,
  folders (unless a rule opts in), files modified in the last 10 seconds.
- Name collision: append " (2)", " (3)"... never overwrite.
- Optional extra: group by month (Sorted/Images/2026-10/). Toggle in settings.
- Use quarantine attribute untouched (do not strip com.apple.quarantine).
- Every move is logged (original path, new path, timestamp) so "Undo last
  organize" can move files back.
- Optional "Source" smart rule: read kMDItemWhereFroms (via MDItem or
  getxattr com.apple.metadata:kMDItemWhereFroms) to route by website/domain,
  e.g. files from a given domain go to a named folder. Real metadata only.
- Live mode uses FSEvents on the watched folder, debounced (wait until file
  size stops changing for ~3 seconds), then applies rules, then posts a
  real notification: "Moved {file} to {folder}". Provide per-notification
  Undo if feasible.
- Also offer "Old downloads" cleanup in the same screen: list files older than
  N days (user-chosen) for Trash. Default off. Review first.

6. CLEANING WHITELIST (REAL LOCATIONS)
--------------------------------------------------------------------------------
Only these are eligible for auto-selection in Smart Scan:
  ~/Library/Caches/*                  (per-app folders, skip running apps)
  ~/Library/Logs/*
  ~/.Trash/*
  Browser caches (only when browser not running):
    Safari:   ~/Library/Caches/com.apple.Safari
    Chrome:   ~/Library/Caches/Google/Chrome
    Firefox:  ~/Library/Caches/Firefox
    Edge:     ~/Library/Caches/Microsoft Edge
  Xcode (only if present):
    ~/Library/Developer/Xcode/DerivedData
    ~/Library/Developer/Xcode/Archives   (list only, unchecked)
    ~/Library/Developer/Xcode/iOS DeviceSupport (unchecked)
    ~/Library/Developer/CoreSimulator/Caches
  Dev caches (only if present, unchecked by default):
    ~/.npm/_cacache, ~/Library/Caches/pip, ~/Library/Caches/Homebrew,
    ~/.gradle/caches, ~/.cache
Listed but ALWAYS unchecked and clearly labeled:
  ~/Library/Application Support/MobileSync/Backup (iPhone backups)
  Old Downloads, large files, duplicates, app leftovers.
Never touched: everything in the section 2 blocklist.

--------------------------------------------------------------------------------
7. WORKFLOWS
--------------------------------------------------------------------------------
7.1 APP START
  Launch -> load settings + history from local store
         -> run Full Disk Access probe
              granted     -> Dashboard
              not granted -> Permission screen (limited mode allowed)
         -> read real disk capacity, render Dashboard
         -> kick off background "top folders" size computation
         -> if auto-organize ON, start FSEvents watcher

7.2 SMART SCAN -> CLEAN
  User taps Start Scan
   -> for each category in whitelist order:
        enumerate real folders, compute sizes, skip protected + running apps
        stream progress to UI (files scanned, current path)
   -> show Results (Review screen). Default-check only whitelist categories.
   -> user opens "Review >" to inspect/uncheck items
   -> user taps "Move selected to Trash"
   -> confirmation sheet (items, size)
   -> for each item: isPathProtected? running app? -> else trashItem
        record (originalURL, resultingItemURL, size) in history
   -> measure free space before/after, show Done screen with real numbers
   -> Undo available from Done screen and History

7.3 DOWNLOADS ORGANIZE (MANUAL)
  Open Downloads Organizer -> enumerate real files in watched folder
   -> apply rules in order, first match wins -> build move plan
   -> Preview screen (user can edit rules, exclude files)
   -> user taps Organize -> perform moves with collision handling
   -> log every move -> show summary "Moved {n} files" + [ Undo ]

7.4 DOWNLOADS ORGANIZE (AUTO / LIVE)
  FSEvents fires on new item in watched folder
   -> debounce until file stops growing and is not an in-progress extension
   -> match rule -> move -> log -> notify "Moved {file} to {folder}"
   -> if no rule matches, leave the file alone (or Other if enabled)

7.5 LARGE FILES / DUPLICATES
  User sets filters -> Scan -> real results list (nothing preselected)
   -> user ticks items -> confirm -> trashItem -> log -> summary

7.6 UNINSTALL APP
  Select app -> find leftovers by bundle ID -> list with sizes (checked)
   -> if app running, offer Quit -> confirm -> trash app + selected leftovers
   -> log -> summary

7.7 UNDO
  History row -> Undo -> for each logged item:
     resultingItemURL still exists in Trash -> move back to originalURL
     (if originalURL taken, restore with " (restored)" suffix)
     else mark "Not recoverable - Trash was emptied"
   -> report real count restored/failed

--------------------------------------------------------------------------------
8. EDGE CASES TO HANDLE
--------------------------------------------------------------------------------
- Permission denied on a path: skip it, count it, show "{n} items skipped (no
  permission)". Never crash, never pretend it was scanned.
- Scan cancelled by user: stop cleanly, show partial real results, label them
  "Partial scan".
- Disk almost full: trashing does not free space until Trash is emptied. If
  user wants immediate space, offer "Empty Trash" as a separate real action
  with its own confirmation, and report real free-space change.
- Files with huge counts (node_modules, caches): enumerate lazily with
  FileManager.enumerator and skip package contents where appropriate. Keep UI
  responsive (batch UI updates, e.g. every 200ms).
- External volumes: label clearly, do not clean ejected/readonly volumes.
- Cloud placeholders (iCloud Drive evicted files): sizes may be 0 on disk;
  never treat them as junk, never trigger a download during scan.
- Time Machine local snapshots, APFS purgeable space: display purgeable space
  as info only ("macOS manages this"), do not try to delete it.
- Localization: use real byte formatting via ByteCountFormatter.

--------------------------------------------------------------------------------
9. DESIGN GUIDELINES
--------------------------------------------------------------------------------
- Native macOS look: SF Symbols, system fonts, vibrancy sidebar, light/dark mode.
- One clear primary button per screen.
- Calm colors. Use red only for destructive confirmations.
- Always show size next to every item, always show the path on hover or in the
  row subtitle.
- Plain language: "Move to Trash", not "Purge". Say what will happen and what
  can be undone.
- Keyboard shortcuts: Cmd+R rescan, Cmd+Delete on selection triggers the
  review/confirm flow (never deletes instantly).
- Accessibility: VoiceOver labels on every control, no color-only meaning.
